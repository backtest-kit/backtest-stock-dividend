# Фонд акций UzSE: годовое удержание с дивидендами

## Что делает стратегия

Каждый календарный год это отдельная папка `content/<yyyy>/` с самодостаточным кодом: `main.strategy.ts` (издержки, депозит, корзина года, карта эмитентов, выход по времени, начисление дивидендов), `classes/UzSE.ts` (дневные свечи акции из Excel-выгрузки биржи), `classes/UzSEDividends.ts` (таблица дивидендов биржи) и `modules/backtest.module.ts` (адаптер биржи с семплированием минуток из дневок через `getCandlesSampled` и годовой фрейм). Общего кода между годами нет, папки штампуются копипастой из эталона `content/2021/`.

Правила фонда:

- Депозит 10 000 000 сумов делится поровну между бумагами корзины года. Все суммы стратегии и отчётов в сумах; сводка дополнительно пересчитывает результат года в доллары по курсу `UZS=X` на начало и конец года.
- Корзина года Y: акции UzSE, которые в году Y−1 торговались не реже 90% дней с медианным дневным оборотом от 1 млн сумов, с историей от начала Y−1, топ-10 по обороту. Список известен до начала года, заглядывания вперёд нет. На практике это 3–9 имён: больше ликвидных акций на бирже нет.
- Каждая позиция открывается на первом часовом тике 1 января и закрывается по времени в 23:59 31 декабря: `minuteEstimatedTime` считается от момента входа до конца года, поэтому и перезаход после стопа закрывается в ту же минуту. Стоп −50% на годовом удержании срабатывает (считается по дневному минимуму), после него бумага перезаходит на следующем тике до конца года. Тейк +2000% технический.
- Дивиденды: на каждом шаге движка `listenActivePing` проверяет по эмитенту позиции решения собраний с датой не позже текущего времени движка. Решение, принятое за время жизни позиции и ещё не начисленное этой позиции за этот финансовый год, начисляется через `commitDividend` суммой `дивиденд на акцию × cost / priceOpen`. Движок складывает её в `pnlCost` и `pnlPercentage`, в `dump/report/strategy.jsonl` появляется строка `action: "dividend"`; стоп и тейк начисление не трогает.
- Издержки в `setConfig` стратегии: `CC_PERCENT_FEE: 0.15` (брокер и биржа за сделку) и `CC_PERCENT_SLIPPAGE: 0.5` (половина спреда ликвидной бумаги), движок применяет оба на входе и на выходе, круг 1.3%. `CC_MIN_TAKEPROFIT_DISTANCE_PERCENT: 2` нужен валидатору: минимальная дистанция тейка должна покрывать круг. Тариф своего брокера подставьте сюда, в сводке та же цифра стоит в `ROUND_TRIP_COST`.

## Подготовка

Движок ждёт Mongo и Redis (`config/loader.config.ts`), поднимаются из `docker/`:

```bash
npm install
docker compose -f docker/mongo/docker-compose.yaml up -d
docker compose -f docker/redis/docker-compose.yaml up -d
```

Данные биржи качаются по требованию в постоянную папку `os.tmpdir()/backtest-kit/uzse/`:

- `<TICKER>_<ISIN>.xlsx` это Excel-выгрузка биржи по бумаге за всю историю (`/isu_infos/export`, очередь заданий). Биржа пускает единицы выгрузок за полчаса и в ответе 429 называет срок ожидания; класс ждёт его и повторяет (до четырёх окон), поэтому холодный старт года из пяти бумаг занимает до часа. Файл качается как `.part` и переименовывается только целиком: битая выгрузка не читается. Повторный запуск в сеть не ходит.
- `dividends.html` это страница `/dividends` с таблицей `window.DIVIDENDS_DATA` по всем эмитентам (92 эмитента, финансовые годы с 2018). Качается один раз.

Чтобы обновить данные до сегодняшнего дня, удалите файл из этой папки.

## Пересборка корзин и папок годов

```bash
node scripts/common/build_universe.mjs            # корзины по ликвидности -> scripts/common/universe.json
node scripts/common/generate_months.mjs           # папки content/<yyyy>/ и раннеры
```

Сборщик берёт дневные ряды всех акций рынка `STK` со страниц биржи (`/isu_infos/STK?isu_cd=...&begin_date=..&end_date=..`, ряд лежит прямо в HTML), кэш в `tmp/uzse/pages/`, `--refresh` перекачивает. По каждому году он печатает корзину и причины исключений: мало торговых дней, редкие сделки, нет id эмитента, дробление внутри года. Ряды биржи не скорректированы на дробления: скачок закрытия между соседними торговыми днями со сделками в 1.8 раза вверх или до 0.55 вниз считается дроблением, и бумага не торгуется в этом году (так исключены UZMK в 2022, HMKB и URTS в 2024). Это единственное правило, которое смотрит на данные самого года, и оно про чистоту ряда, а не про доходность.

Карта тикер → id эмитента в таблице дивидендов лежит в `scripts/common/uzse_issuers.json` и собрана вручную по названиям (в справочнике тикеров названия на латинице, в таблице дивидендов на русском). Бумага без записи в карте в корзину не попадает: без дивидендов тест акций UzSE неверен. Новый ликвидный тикер требует одной строки в этом файле.

Генератор копирует эталонную папку во все завершённые годы, подставляя блоки `BASKET:BEGIN..BASKET:END` и `ISSUERS:BEGIN..ISSUERS:END` в стратегии и фрейм в модуле биржи, копирует `classes/` и переписывает раннеры `scripts/linux/run_strategy.sh` и `scripts/win/run_strategy.bat`. Чтобы изменить стратегию, правьте эталон `content/2021/main.strategy.ts` и запускайте генератор заново.

## Прогон

Один год:

```bash
npm start -- --backtest --entry ./content/2021/main.strategy.ts
```

Все годы подряд:

```bash
bash scripts/linux/run_strategy.sh        # scripts\win\run_strategy.bat на Windows
```

Отчёт года: `content/<год>/dump/report/backtest.jsonl`, строки `opened`, `active` и `closed` по каждому сигналу; `closeReason: "time_expired"` это штатный выход 31 декабря, `stop_loss` это срабатывание −50%. Начисленные дивиденды лежат в `dump/report/strategy.jsonl` строками `action: "dividend"` с суммой и временем. Каждый год завершает процесс через `kill()` с ненулевым кодом, раннеры это не считают ошибкой.

Сводка по всем годам:

```bash
node scripts/common/summarize_reports.mjs
```

Таблица по годам: число бумаг, нетто в сумах и в процентах от депозита, вклад цены и вклад дивидендов отдельно, оценка издержек, результат в долларах по курсу года, причины закрытий; кумулятивный P&L с просадкой; список закрытий не по времени. Год с числом `opened`, не равным `closed`, оборван, его надо перепрогнать.

## Известные допущения

- **Дата решения вместо даты реестра.** Биржа публикует дату собрания и окно выплаты, но не дату закрытия реестра. Дивиденд начисляется в день решения; реальный реестр закрывается на несколько дней раньше или позже, и цена «очищается» от дивиденда в другой день. На годовом удержании это сдвиг внутри позиции, а не ошибка суммы, кроме бумаг, купленных или проданных по стопу в неделю вокруг собрания.
- **Семплирование.** High, low и close дневного бара известны только к концу дня, а семплированные минутки несут их с утра. Для выхода по времени это не влияет, стоп −50% срабатывает по дневному минимуму.
- **Ликвидность.** Пороги подобраны под депозит 10 млн сумов: позиция в 1–3 млн сумов проходит за день-два в бумагах с медианным оборотом от 1 млн. Депозит в десятки раз больше потребует других порогов и другого проскальзывания.
- **Раздельный учёт.** У движка нет общего портфельного баланса: каждая бумага это отдельный бектест, «фонд» существует как арифметика долей плюс сумма `pnlCost` по отчёту года. Депозит фиксированный, результаты годов не реинвестируются.
- **Дробления.** Исключаются правилом, а не корректируются; бумага пропускает год дробления целиком.
